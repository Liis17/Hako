# Modrinth

Parent: [[Index]]

## Назначение

Каталог Modrinth для сборки: поиск модов Fabric, ресурспаков и датапаков выбранного мира, выбор совместимой версии, проверка загрузки
и установка вместе с обязательными зависимостями. Отдельный каталог готовых модпаков создаёт независимые Vanilla/Fabric-сборки из `.mrpack`. Страница каталога описана в [[UI/Launcher]];
официальный Fabric API при создании сборки — в [[Minecraft/Installation]].

## Клиент

`ModrinthClient` — actor поверх `https://api.modrinth.com/v2` с User-Agent Hako; запросы только по HTTPS,
идентификаторы проектов — ASCII-буквы и цифры. `InstanceContentController` получает клиент параметром `init`
(по умолчанию — новый `ModrinthClient`), тесты подменяют `URLSession` и каталог кеша.

| Метод | Запрос | Контракт |
|-------|--------|----------|
| `search(_:kind:minecraft:sort:offset:)` | `GET /search`, `limit=20` | Пустой запрос не передаётся; `+` кодируется как `%2B`. `ModrinthSort`: relevance, downloads, newest, updated |
| `compatibleVersions(project:kind:minecraft:)` | `GET /project/{id}/version` | Точная версия Minecraft и загрузчик `fabric` (моды), `minecraft` (ресурспаки) или `datapack` (датапаки), только версии с устанавливаемым файлом; release → beta → alpha, внутри канала — новейшие по `date_published` |
| `latestVersion(project:kind:minecraft:channel:)` | то же | Первая из `compatibleVersions`; с `channel` — новейшая только этого канала |
| `projects(_:)` / `versions(_:)` | `GET /projects`, `GET /versions` | Названия, иконки и типы зависимостей; проект по `version_id` |
| `versions(of:)` | `POST /version_files` (`sha512`) | `URL → ModrinthFileMatch` (проект, версия, дата, SHA-512); хеши и известные версии берутся из кеша |
| `latestVersions(for:kind:minecraft:)` | `POST /version_files/update` | Новейшие версии по хешам с загрузчиком выбранного вида; `version_types` запрашиваются по очереди release → beta → alpha только для ненайденных хешей; прежний адаптер `mods:` сохранён |
| `download(_:into:)` | URL файла | Временный файл переносится под именем из Modrinth; размер и SHA-512 обязаны совпасть |

Фасеты модов: `project_type:mod`, `categories:fabric`, `versions:<mc>`, `environment!=dedicated_server_only` —
скрыты только моды выделенного сервера; `server_only` работает во встроенном сервере одиночной игры и показывается. Ресурспаков: `project_type:resourcepack`, `versions:<mc>`.
`ModrinthVersion.file(kind:)` выбирает primary либо первый `.jar`/`.zip` без `sources/dev/javadoc-jar`,
с HTTPS, ненулевым размером, SHA-1 и SHA-512; версия без такого файла не устанавливается.
При выборе датапака исключаются файлы `required-resource-pack` и `optional-resource-pack`.
`ModrinthVersion.resourcePacks` возвращает такие ZIP-файлы с теми же проверками, сначала обязательные,
затем необязательные; внутри типа — по имени файла. Они принадлежат той же версии, отдельный проект не нужен.
Датапаки: `all_project_types:datapack`, `categories:datapack`, `versions:<mc>`;
основной `project_type` может быть `mod`, поэтому тип файла определяется выбранным `kind` и загрузчиком версии.
`ModrinthContentKind` содержит `.mod`, `.resourcePack`, `.datapack` (JAR для модов, ZIP для остальных).
`ModrinthInstallTarget` содержит `.mods`, `.packs`, `.worldDatapacks(String)`; строка — имя папки мира.
Клиент, контроллер и каталог сохраняют адаптеры `mods: Bool` для прежних вызовов.
`ModrinthProject.pageURL` — `https://modrinth.com/{project_type}/{slug ?? id}`.

## Установка

`install` выполняется через общий `perform`: действуют `disabledReason`, блокировка `contentBusy`
и очередь подтверждений. `catalogInstalling[instanceID]` хранит проект, `catalogInstallTargets[instanceID]` —
назначение; индикатор показывается только в соответствующем каталоге.

1. Новейшая совместимая версия выбранного проекта в канале `install(_:in:target:channel:)` (по умолчанию `release`;
   каталог передаёт `beta`/`alpha` из меню «⋯»). Её отсутствие — ошибка «нет релиза/беты/альфы».
   Зависимости канал не наследуют.
2. Обязательные (`required`) зависимости обходятся в ширину, включая зависимости зависимостей, до 30 проектов.
   Установленные и включённые пропускаются; отключённые помечаются «Отключён — будет включён»;
   отсутствующие получают последнюю совместимую версию или пометку «Нет совместимой версии».
   Моды-зависимости ставятся только в Fabric-сборку вне очереди/установки («Нужна сборка с Fabric»);
   Для установки в мир сначала ищется совместимая datapack-версия зависимости, включая проекты типа `mod`.
   Датапаки идут в тот же мир, ресурспаки — в сборку, Fabric-моды — в сборку с Fabric;
   остальные типы — «Не поддерживается Hako».
3. Если список не пуст, модалка «Нужны зависимости» предлагает «Добавить с зависимостями»
   (нет кнопки, если ставить нечего), «Только мод»/«Только ресурспак»/«Только датапак» или «Отмена».
4. Для каждого датапака в выбранном плане установки, включая зависимости, связанные ресурспаки из `files`
   предлагаются отдельной модалкой «Ресурспак для датапака». `ContentConfirmation.resourcePacks` содержит варианты,
   `ContentChoice.resourcePack(String)` передаёт имя выбранного файла. По умолчанию выбран первый;
   «Добавить с ресурспаком» добавляет ровно один вариант в сборку, «Без ресурспака» пропускает его,
   «Отмена» отменяет всю операцию до изменения файлов. Ресурспак нужно включить в Minecraft самостоятельно.
   Совпадение по SHA-512 с локальным файлом исключает повторную загрузку; отключённый файл включается.
5. Все файлы загружаются во временную папку и проверяются до изменения сборки. Для JAR читается
   `fabric.mod.json`: `fabricloader` сравнивается с закреплённым Loader, `java` — с Java сборки, если она известна;
   без `fabric.mod.json` или с нечитаемым предикатом проверка пропускается. Зависимости `incompatible` версий плана
   сверяются с включёнными проектами сборки и для датапаков — выбранного мира. ZIP датапака должен
   содержать читаемый JSON `pack.mcmeta` с объектом `pack` в корне архива. Найденное показывается модалкой «Возможна несовместимость»
   с «Установить всё равно»/«Обновить всё равно» (destructive) и «Отмена»; отмена не меняет сборку.
6. Публикуются зависимости, выбранный проект и выбранные связанные ресурспаки; коллизия имени проходит через подтверждение замены.
   Отключённые зависимости включаются. Перечитываются все затронутые назначения.

Моды записываются в `minecraft/.hako-mods.json`, ресурспаки — в `minecraft/.hako-resourcepacks.json`
(также для старой папки `texturepacks`), датапаки — в `.hako-datapacks.json` внутри выбранного мира.
`ModOrigin` содержит происхождение Modrinth: проект, ID и номер версии, страницу, иконку и SHA-512;
новые необязательные поля совместимы с прежним реестром модов.
В списке появляются источник, установленная версия и ссылка на страницу. Fabric API сохраняет `FabricAPIDescriptor`,
поэтому продолжает получать обновления. Локальный импорт стирает происхождение файла.

Датапаки публикуются через `InstanceContent.importDatapack` в `minecraft/saves/<мир>/datapacks`,
ZIP остаётся архивом. Перед публикацией мир проверяется повторно; исчезнувшие родители не создаются
([[Minecraft/Worlds]]). `level.dat` не меняется. Сообщение успеха и локальные списки контроллера
привязаны к UUID сборки и имени папки мира; отмена замены не показывает успех.

## Обновления

`checkAllUpdates(_:target:)` вызывается при открытии раздела, раскрытии мира и кнопкой «Проверить обновления»;
адаптер `mods:` сохранён. Для модов Fabric API
проверяется прежним `checkUpdates`; остальные файлы раздела (кроме папок и API) — `checkModrinthUpdates`:
`versions(of:)` → `latestVersions`. Обновление предлагается, если файл новой версии отличается по SHA-512
и версия опубликована позже текущей — так установленная beta не сменяется более старым release.
Результат — `modrinthUpdates[«сборка:раздел»][имя файла]`, для датапаков ключ включает имя папки мира;
ошибки сети — `modrinthUpdateMessages`, список остаётся. Распознанные прежние файлы получают сохранённые
источник, номер версии и иконку проекта. Датапаки запрашиваются с загрузчиком `datapack`, ресурспаки — `minecraft`.
Для связанных ресурспаков из файлов датапака используется загрузчик `datapack`, затем выбирается ZIP
ресурспака с тем же `file_type`: точное имя или единственный подходящий файл. Несколько вариантов
без точного совпадения имени не обновляются автоматически.

`updateFromModrinth` идёт тем же конвейером, что установка (зависимости, загрузка, совместимость), но вместо
импорта вызывает `InstanceContent.replaceItem`: старый файл сверяется с ожидаемым SHA-512, новый занимает его место
с сохранением отключения (`.jar.disabled` либо папка отключённых паков), соответствующий реестр получает
происхождение Modrinth; ошибки откатывают замену. Для датапаков `replaceDatapack` повторно проверяет существование мира
на файловом акторе. `updateAPI` после своих проверок использует тот же `replaceItem`.

`updateAll(_:target:)` (с адаптером `mods:`) применяет все доступные обновления раздела или выбранного мира подряд одним `perform`: сначала Fabric API
(`applyAPIUpdate`), затем файлы Modrinth через `installFromModrinth(..., interactive: false)`. Без `interactive`
вместо диалогов зависимостей и несовместимости обновление до изменения сборки отменяется ошибкой «требует
подтверждения — обновите отдельно»; ошибки по файлам собираются в `errors[instance.id]`, остальные обновления
продолжаются. `hasUpdates` сообщает, есть ли что обновлять.

## Кеш

`ModrinthClient` хранит `Library/Caches/Hako/Modrinth/files.json`: SHA-512 по пути, размеру и дате изменения
файла и найденную версию по хешу. Неизменённые файлы не хешируются, известные хеши не запрашиваются.
Хеши без проекта помнятся только до закрытия Hako. Записи удалённых файлов отбрасываются при сохранении,
битый файл кеша игнорируется. URL сбрасывает закешированные `resourceValues`, иначе изменения файла не видны.

## Распознавание установленного

`installedProjects` возвращает `projectID → файлы`: моды и паки с происхождением Modrinth из реестров и
остальные файлы (кроме папок-паков), распознанные через `versions(of:)` по SHA-512 с кешем. Поэтому вручную
скачанные с Modrinth файлы тоже считаются установленными. Отключённые файлы входят в результат. Для датапаков проверяются только файлы выбранного мира;
включая отключённые ZIP в `.hako-disabled-datapacks` этого же мира. Папки датапаков по хешу не распознаются. Включение зависимости направляется в тот же мир с повторной проверкой его существования.

## Ограничения

- Зависимости `optional` и `embedded` не проверяются.
- Несовместимость проверяется только по объявлениям новых версий; объявления уже установленных модов не читаются.
- Несовместимое обновление Fabric API по-прежнему не предлагается (`checkUpdates`).

## Windows-клиент: Core этапов 6b/7b и UI этапов 6c/7c

`windows/Hako.Core/Minecraft/ModrinthClient.cs` расширяет общий клиент, используемый Fabric: поиск с фасетами,
пагинацией и сортировкой, проекты и версии по ID, проверка совместимых версий по фактическим `game_versions`
и `loaders`, сопоставление SHA-512 и проверяемые потоковые загрузки. Кеш `Modrinth/files.json` размещается
под инжектируемым `HakoPaths.CacheRoot`; хеши файлов переиспользуются по пути, размеру и времени изменения.
Клиенты в одном процессе с одинаковым путём кеша используют общую блокировку и перечитывают последний снимок перед
сохранением; разные корни не блокируют друг друга, межпроцессная синхронизация не применяется. Метаданные ограничены
по размеру, URL загрузки должны быть HTTPS.

`windows/Hako.Core/Instances/InstanceContent.cs` предоставляет локальные операции для JAR-модов, ресурспаков и
датапаков. `InstanceContentTarget` различает `.Mods`, `.Packs` и `.WorldDatapacks(worldId)`; старые overload-ы по
`ModrinthContentKind` сохраняют контракты модов/ресурспаков и отвергают датапак без папки мира. Список включает
отключённые файлы; отключённые JAR сохраняют имя с `.jar.disabled`, ресурспаки и датапаки переносятся в соседние
`.hako-disabled-resourcepacks`/`.hako-disabled-texturepacks` и `.hako-disabled-datapacks`.
Папки обходятся без перехода по reparse points; ZIP остаются архивами. Для датапака `pack.mcmeta` должен быть
единственным обычным корневым ZIP entry или корневым файлом папки, не больше 1 МиБ, корректным JSON-объектом с
объектом `pack`; число ZIP entries ограничено 100 000, чтение метаданных можно отменить. В мире создаётся только leaf
`datapacks`, если выбранная папка мира и её level metadata всё ещё существуют.
Импорт очищает происхождение, замена сверяет ожидаемый SHA-512 и сохраняет disabled-состояние; при ошибке новый файл
удаляется, а старый и коллизия восстанавливаются независимо. Реестр мира — `.hako-datapacks.json`; отсутствие
`apiProvisioned` совместимо с данными Swift. Повреждённый реестр не перезаписывается. Публичные мутации сериализованы
content-lease сборки; контроллер повторно проверяет целевой мир под тем же lease перед публикацией.

`windows/Hako.Core/Instances/InstanceContentController.cs` координирует локальные операции, каталог и обновления
без WinUI. Публичные методы чтения, установки и обновления имеют overload-ы с `InstanceContentTarget`; target-методы
доступны для локального импорта, переключения, проверки и обновления датапаков выбранного мира. Удаление отдельных
датапаков не предоставляется. `InstanceContentState` адресуется по `InstanceContentStateKey(instanceId, kind, worldId)`;
для модов и ресурспаков `worldId` равен null. `GetState` возвращает снимок, а `StateChanged` передаёт новый снимок
на потоке, где завершилась операция. WinUI переносит обновление на `DispatcherQueue`.
Состояние содержит локальные файлы, обновления, ошибки с кодом и аргументами, busy/checking, текущий проект и сообщения.
Ошибки чтения публикуются только в ревизию, в которой началось чтение; они не меняют ревизию активной мутации.
Проверка busy и начало чтения (revision + loading/checking) атомарны с началом мутации под общей блокировкой состояния.
Мутация, включая зависимости другого kind, фиксирует revision и busy до первого события; обработчики вызываются вне
блокировки. Чтение занятого раздела не меняет revision, поздние результаты прежнего чтения отбрасываются.
Busy снимается владельцем per-instance operation gate независимо от ревизий чтения.

При обновлении с подтверждённой коллизией `ReplaceUnderLeaseAsync` получает `confirmedCollision`: старый файл,
коллизия и registry публикуются одной обратимой операцией под существующим lease. До commit registry коллизия
хранится в backup; отмена или ошибка восстанавливает оба исходных файла независимо. После commit коллизия
отправляется в корзину без отмены caller-а; отказ/отмена Shell сохраняет backup, новая версия уже установлена,
но результат операции содержит `ContentOperationFailed`. Аргумент `diagnostic` сохраняет сведения об ошибке и пути
оставшихся backup для диагностики; UI локализует код ошибки, а не использует diagnostic как текст интерфейса.
Состояние после такой ошибки перечитывается и отражает фактические файлы.

`ContentConfirmationRequest` передаёт коды, аргументы, проекты, иконки и коды пояснений. Для связанных файлов версии
датапака `Files` содержит filename, file type и required/optional; additive `ContentConfirmationSelectionCallback`
возвращает выбор имени файла и не меняет прежний `ContentConfirmationCallback`. Старый callback с ответом `Primary`
выбирает первый файл, `Alternative` продолжает без ресурспака, `Cancel` отменяет установку до загрузки и публикации.
Новый callback тоже может вернуть `Primary` без имени — используется первый файл. UI локализует коды; callback принимает
`CancellationToken`, а отмена снимает ожидание подтверждения. Вызов без callback отменяет операции, которым нужно
подтверждение. WinUI диалог показывает файлы с пометками required/optional, выбирает первый файл по умолчанию и
передаёт выбранный filename только при основном действии; альтернативное действие продолжает без связанного
ресурспака, закрытие окна отменяет ожидание. Каталог поиска остаётся в UI и использует `ModrinthClient.SearchAsync`.

Связанный ресурспак с уже установленным SHA-512 используется без изменения происхождения: существующий origin
сохраняется целиком, локальный файл остаётся без origin. Отключённый файл включается после подтверждений и успешной
установки датапака. Новый загруженный ресурспак получает origin выбранной версии и её `file_type`.

Контроллер строит обязательные зависимости breadth-first (до 30 проектов), разрешает зависимость только по `version_id`,
проверяет установленные по происхождению или SHA-512 файлы, предлагает включить отключённые и показывает отсутствующие,
неподдерживаемые и несовместимые элементы. Для цели мира сначала ищется совместимая datapack-версия зависимости,
включая проект Modrinth с `project_type:mod`; такой файл ставится в тот же мир. Ресурспак-зависимости идут в `.Packs`,
а моды — в `.Mods` только у Fabric. Если доступна только версия мода, неподдерживаемая цель или нет совместимой версии,
подтверждение показывает соответствующий note code. Root может выбирать release/beta/alpha; зависимости берут последнюю
совместимую версию независимо от канала root. Все выбранные файлы сначала загружаются в отдельные подпапки
`%TEMP%/Hako-Modrinth-*`, сверяются клиентом по размеру, SHA-1 и SHA-512, а каждый staged ZIP датапака дополнительно
проверяется по `pack.mcmeta`. Перед публикацией проверяются совместимость Fabric Loader/Java для модов, несовместимости
только в сборке и выбранном мире, и коллизии имён. Операция удерживает один `InstanceStore` content-lease; внутренние
методы `InstanceContent.*UnderLeaseAsync` повторный lease не захватывают. После отмены или ошибки снимки затронутых
target-ов перечитываются.

`CheckUpdatesAsync` отдельно проверяет Fabric API по закреплённому Loader и сохраняет его `FabricApiDescriptor`.
Обновление API использует общий план коллизий: одиночное обновление запрашивает подтверждение замены чужого файла,
отказ и отмена оставляют файлы без изменений; bulk возвращает `ConfirmationRequired` без диалога. Подтверждённая
коллизия передаётся в ту же обратимую замену, с сохранением отключённого состояния и API descriptor.
Другие файлы распознаются по SHA-512; распознанным файлам без происхождения запись добавляется под lease только при
совпадении ожидаемого хеша. Обновление требует отличающийся SHA-512 и дату строго новее установленной; при более старом
release поиск продолжается для beta/alpha. Связанные `required-resource-pack` и `optional-resource-pack` версии датапака
обновляются как ресурспаки с loader `datapack`, по прежнему `file_type` и точному имени либо единственному подходящему файлу.
`UpdateAllAsync` обрабатывает Fabric API первым, затем файлы последовательно, без диалогов; элементам, которым требуется
подтверждение, записывается `ConfirmationRequired`, остальные продолжают обновляться.

`windows/Hako/App.xaml.cs` создаёт один app-lifetime `ModrinthClient`, `InstanceContent` и
`InstanceContentController`; экземпляр Modrinth общий с `FabricClient`. В UI профиль сборки держит разделы «Моды»
(только Fabric), «Ресурспаки», «Миры» и «Настройки». `InstanceContentView` и `ModrinthCatalogView` используют
`InstanceContentTarget`; kind-overload оставлен совместимым для модов и ресурспаков. Локальные списки и каталог
размещены внутри `InstanceContentView`, поэтому возврат из каталога не пересоздаёт профильный черновик. Picker
принимает JAR для модов, ZIP/папки для ресурспаков и датапаков; drag-and-drop фильтруется теми же правилами,
импорт идёт последовательно через контроллер. Карточка мира настраивает target с конкретным worldId, а UI скрывает
удаление отдельных датапаков.

`InstanceContentView` подписывается на `StateChanged` только пока раздел виден. Событие может прийти с потока Core;
UI ставит coalesced refresh в `DispatcherQueue`, затем читает последний снимок через `GetState(instanceId, target)` и
не применяет ревизию ниже уже отображённой. При уходе со страницы отменяются только её чтение и поиск, начатая
установка остаётся app-lifetime операцией. Проверка обновлений запускается при открытии раздела и сохраняет список
файлов при сетевой ошибке.

`ModrinthCatalogView` запрашивает точную версию Minecraft и тип контента, сортирует по четырём режимам и загружает
страницы по 20 проектов. Изменение запроса отменяет прежний поиск и повышает его generation до debounce; поздний
результат не заменяет новый. При ошибке первой страницы показывается повтор, при ошибке пагинации прежняя лента
сохраняется. Установленные проекты сопоставляются контроллером по origin или SHA-512, включая отключённые файлы.
Кнопка добавления выбирает release; совместимые beta/alpha доступны в меню проекта. Подтверждения и ошибки Core
сопоставляются с ru/en строками через `ContentResourceKeys` и сериализуются общим `HakoDialogs` на `XamlRoot`.

Форматы реестров, source generation и cache изоляция остаются контрактами Core выше. Windows UI этапа 7c выбирает
мир через профиль сборки, показывает его target-контент и возвращает из каталога к той же раскрытой карточке.

## Решения и основания

Решения пользователя: предлагать установку недостающих зависимостей, ставить последнюю совместимую версию,
поиск, сортировка, скрытие модов только для выделенного сервера (`server_only` вроде Async работает в одиночной игре) и проверка Loader/Java; несовместимость — предупреждение с установкой
на выбор пользователя; «Добавить» в каталоге ставит только релиз, бета и альфа — явным выбором в меню «⋯»; обновления модов и ресурспаков; кеш хешей на диске. На кнопке — SF Symbol `shippingbox`,
как у бейджа источника: использование логотипа Modrinth требует письменного разрешения Rinth, Inc.
(`COPYING.md` в репозитории `modrinth/code`).

## Готовые модпаки

`ModrinthClient.searchModpacks(_:minecraft:sort:offset:)` использует `project_type:modpack`, OR-фасет
`categories:fabric`/`categories:minecraft`, исключает dedicated-server-only и добавляет точный Minecraft,
если выбран фильтр. `modpackVersions(project:minecraft:)` повторно проверяет проект, Minecraft, загрузчики
конкретной версии и `.mrpack` с HTTPS, размером и SHA-1/SHA-512; порядок — release → beta → alpha,
внутри канала — по дате. Контракты отдельных модов и паков сохранены.

`Minecraft/ModpackManifest.swift` задаёт `ModpackManifest`, `ModpackPlan` и `PreparedModpack`.
Поддерживаются formatVersion 1, game minecraft и зависимости `minecraft`, необязательная `fabric-loader`;
неизвестные зависимости отклоняются. `Minecraft/ModpackInstaller.swift` — actor, принадлежащий
общему `InstallationCoordinator`. Подготовка проверяет архив, точную версию Minecraft через `MojangClient.prepare`
и закреплённый Loader/профиль через Fabric Meta; автоматический Fabric API не запрашивается.

`Minecraft/ModpackArchive.swift` читает системным `unzip` список записей и индекс; выбранные записи
передаются через stdout в обычные файлы staging без прав и ссылок из ZIP. Пути проверяются до записи:
запрещены выход из каталога, неоднозначные имена, коллизии файлов/папок и регистра, служебные `.hako*`
и каталоги компонентов игры. Число записей и объём чтения/распаковки ограничены.
Общие overrides применяются первыми, client-overrides заменяют одноимённые файлы; server-overrides пропускаются.

Установка включает required и optional клиентские файлы, пропускает client unsupported.
Файлы скачиваются потоково, не более четырёх одновременно; при сбое пробуются остальные URL.
Для файлов манифеста допустимы HTTPS-хосты cdn.modrinth.com, github.com, raw.githubusercontent.com, gitlab.com.
Архивы и файлы проверяются по размеру, SHA-1 и SHA-512 и кэшируются по SHA-512 в `Library/Caches/Hako/Modpacks`.
Весь состав подготавливается до публикации. Назначения повторно проверяются, существующие симлинки
отклоняются; файлы публикуются только в minecraft/ новой сборки. Ошибка или отмена не дают ready.

Закреплённый план сохраняется в корне сборки как `.hako-modpack.json` до постановки в очередь
([[Data/Persistence]]). Готовность включает Java, Minecraft, Loader и импорт модпака.
После импорта completed предотвращает повторное применение состава при переустановке компонентов игры:
удалённые моды и пользовательские настройки сохраняются. До завершения импорта повтор использует проверенный кэш;
при его отсутствии архив и файлы загружаются заново по закреплённым адресам.
Распознавание отдельных файлов по хешам использует прежний `versions(of:)`.
Импорт локального `.mrpack` и обновление модпака целиком не реализованы.

### Windows-клиент

`windows/Hako.Core/Minecraft/ModrinthClient.cs` использует общий HTTP-клиент Fabric и каталога. `SearchModpacksAsync`
строит facets `project_type:modpack`, OR для Fabric/Minecraft, исключение dedicated-server-only, сортировку,
точный Minecraft-фильтр и offset. `GetModpackVersionsAsync` повторно сверяет `project_id`, `game_versions`,
loaders, канал и наличие installable `.mrpack`; каталог/pagination — `Instances/ModpackCatalog.cs`.

Windows `Minecraft/ModpackArchive.cs` читает central directory напрямую, а файлы распаковывает потоково через
`ZipArchive`. По умолчанию ограничены архив (2 GiB), число записей (50 000), индекс (16 MiB), один файл (2 GiB),
общая распаковка (20 GiB) и central directory (8 MiB). ZIP64, шифрование, ссылки, reparse/device атрибуты,
опасные Windows-пути, коллизии регистра и файлов/каталогов отклоняются до публикации. Разрешённые корни игры,
служебные `.hako*` и пути компонентов запрещены. Common overrides применяются первыми, client overrides заменяют
общие, server overrides игнорируются после проверки путей. Required/optional client-файлы включаются, unsupported
пропускаются; файлы и архив проверяются по размеру, SHA-1 и SHA-512, до четырёх файлов загружаются параллельно.
Кэш SHA-512 находится в `HakoPaths.CacheRoot/Modpacks`. План сохраняется до queue; ready выставляется только после
успешного импорта. `completed` не позволяет повторно применить удалённые пользователем файлы при переустановке.
Локальный импорт `.mrpack` и обновление модпака целиком пока не реализованы.
