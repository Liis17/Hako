# Updates

Parent: [[Index]]

## Назначение

macOS-клиент проверяет стабильные macOS-релизы `macos-vX.Y.Z` в GitHub Releases, скачивает ассет `Hako-<версия>-macos.dmg`, заменяет свой `.app` и перезапускается. Проверка выполняется при запуске и раз в 6 часов с переключателем и кнопкой «Проверить сейчас»; точка на «Настройках» в рейле показывается при доступном обновлении.

Переход уже установленных клиентов из прежнего pre-release `nightly` выполняется вручную. Автоматической совместимости или моста с `nightly` нет. Обновления Windows описаны в [[#Windows-клиент]].

## Совместимость ассетов

CI публикует в каждом новом стабильном macOS-релизе два побайтово одинаковых DMG: `Hako-<версия>-macos.dmg` и `Hako.dmg`. Оба загружаются до публикации draft-релиза и имеют одинаковые размер и SHA-256. Текущий клиент выбирает точное версионное имя; установленный стабильный клиент `1.0.0`, уже понимающий теги `macos-vX.Y.Z`, ищет `Hako.dmg` и благодаря этому получает обновление без ручной переустановки. Это не добавляет поддержку прежнего nightly-протокола.

Скачивание, установка и перезапуск выполняются по кнопке «Обновить и перезапустить»; автоматической остаётся проверка наличия обновления.

## Версия приложения

`macos/Hako/Version.xcconfig` содержит текущую исходную версию `MARKETING_VERSION = 1.0.2` и номер сборки `CURRENT_PROJECT_VERSION = 1`; Debug и Release таргета `Hako` используют этот файл. Настройка `HAKO_COMMIT` пустая в локальной конфигурации и CI задаёт её равной `$GITHUB_SHA`.

Стабильный macOS-релиз имеет тег ровно вида `macos-vX.Y.Z`, без ведущих нулей и дополнительных суффиксов. Текущая версия берётся из `CFBundleShortVersionString`; историческая версия `1.0` сравнивается как `1.0.0`. Сравнение числовое по компонентам, поэтому `1.10.0` новее `1.9.9`.

Стабильные релизы выходят только при изменении платформы с повышением её версии; общий per-push prerelease убран. Гейт `.github/workflows/tests.yml` требует повышения версии изменённой платформы на PR. Автообновление Hako рассматривает только стабильные macOS-теги `macos-vX.Y.Z`.

`AppUpdateCoordinator` получает текущую версию отдельно от коммита. `currentCommit == nil` по-прежнему обозначает локальную сборку: координатор не проверяет сеть, а раздел «О приложении» показывает версию, номер сборки и «локальная сборка». Коммит используется только как происхождение релиза и для проверки установленного приложения, не для определения новизны.

## Публичные контракты

| Контракт | Поведение |
|----------|-----------|
| `AppReleaseClient.latest()` | `GET api.github.com/repos/Liis17/Hako/releases?per_page=100&page=1`; следует по `Link: rel="next"` до конца списка и выбирает максимальную числовую опубликованную стабильную macOS-версию |
| Кандидат `AppRelease` | Тег `macos-vX.Y.Z`, `draft == false`, `prerelease == false`, есть `published_at`, `target_commitish` содержит полный SHA из 40 hex-символов и приложен ассет с именем `Hako-<версия>-macos.dmg`, точно совпадающим с версией тега; релизы Windows, `nightly` и malformed tags игнорируются |
| Пустой список / HTTP 404 | `latest()` возвращает `nil`; проверка записывает успешный результат без сообщения об ошибке и без предложения обновления |
| Ошибки API | Сетевые ошибки, не-2xx статусы кроме 404 и некорректный JSON остаются ошибками ручной проверки; автоматическая проверка их не показывает |
| `AppRelease.isUpdate(for:)` | `true`, только если релиз подходит macOS-клиенту и его числовая версия новее текущей версии бандла |
| `AppRelease.commit` | SHA коммита сборки для проверки происхождения релиза и извлечённого приложения |
| `AppRelease.Asset.sha256` | Из поля `digest` вида `sha256:<hex>`; без него загрузка отклоняется |
| `AppUpdateCoordinator.automaticCheckKey` | `"checkUpdatesAutomatically"` в `UserDefaults.standard`, по умолчанию `true` |

## Установка

1. Отказ, если `InstanceStore.contentBusy` не пуст (повторяется после загрузки): перезапуск прервал бы файловые операции сборок. Очередь установки Minecraft продолжается после перезапуска, игры от лаунчера не зависят ([[Minecraft/Launching]]).
2. `preflight`: путь не содержит `/AppTranslocation/`, папка `.app` доступна на запись — иначе просьба переместить Hako в «Программы».
3. Загрузка во временную папку, проверка размера и SHA-256.
4. `hdiutil attach -nobrowse -readonly -noautoopen` во временную папку `itemReplacementDirectory` на томе приложения, копирование `Hako.app`, `hdiutil detach -force`.
5. Копия должна иметь тот же `CFBundleIdentifier`, числовую `CFBundleShortVersionString`, что версия релиза (старое `1.0` эквивалентно `1.0.0`), и `HakoCommit == release.commit`; затем выполняется `codesign --verify --deep --strict`.
6. `FileManager.replaceItemAt` атомарно заменяет запущенный бандл; `/bin/sh` ждёт выхода текущего PID и вызывает `open`; затем `NSApp.terminate`. Отложенное переименование сборки может отменить выход — тогда новая версия откроется после выхода.

## Ограничения

- Сборки CI подписаны ad-hoc, без Developer ID и нотаризации. Загрузка через `URLSession` не ставит карантин, поэтому заменённое приложение открывается без подтверждения Gatekeeper.
- Анонимный GitHub API ограничен 60 запросами в час с IP; проверка раз в 6 часов в него укладывается.
- В macOS 27 `hdiutil attach/detach` выводит предупреждение об устаревании, но работает.

## Windows-клиент

`windows/Hako.Core/Updates/` содержит `AppReleaseClient`, `AppUpdateDownload` и `AppUpdateCoordinator`; WinUI и системная установка находятся в `windows/Hako/WindowsAppUpdateService.cs`, отображение — в `SettingsPage.Updates.cs` и `MainWindow`. Общий экземпляр принадлежит `LauncherServices.Updates`; `App` запускает планировщик после восстановления игровых процессов и останавливает его при закрытии.

### Проверка и загрузка

- Анонимный `GET /repos/Liis17/Hako/releases?per_page=100` следует по всем `Link: rel="next"` и выбирает максимальный числовой опубликованный стабильный `windows-vX.Y.Z` с точным ассетом `Hako-X.Y.Z-windows-{x64|arm64}.msix`. Общий `/releases/latest` не используется: релизы платформ независимы. JSON читается через `HakoJsonContext` без рефлексии.
- Версия и архитектура берутся из `Package.Current.Id`; одинаковые и более старые версии не предлагаются. В unpackaged, development, preview и изолированных запусках обновление установленного приложения отключено.
- Автопроверка включена по умолчанию, запускается при старте и раз в шесть часов. Переключатель `checkUpdatesAutomatically` хранится в `ApplicationData.Current.LocalSettings`, не меняя `settings.json`. Автоматические ошибки не открывают диалогов; ручные ошибки видны в настройках.
- По кнопке «Обновить» файлы потоково загружаются в `<ApplicationData.Current.LocalCacheFolder.Path>/Hako/Cache/AppUpdates/<GUID>` с прогрессом, отменой и таймаутом. Используется физический путь кеша пакета: обычный `LocalAppData/Hako/Cache` виртуализируется внутри MSIX и недоступен службе развёртывания по исходному пути. Очистка старых загрузок использует тот же физический корень. Обязательны размер и GitHub `digest` SHA-256. Основной MSIX должен совпадать с установленным Name/Publisher/архитектурой и версией тега; XML-манифест читается с запретом DTD и ограничением размера.
- Ассеты `Hako-X.Y.Z-windows-<архитектура>-dependency-*.(msix|appx)` проверяются по размеру и SHA-256; допустимы архитектура основного пакета и `neutral`. Они передаются Windows как зависимости. Неполные и повреждённые загрузки удаляются; перед установкой хеши проверяются повторно. Старые собственные каталоги загрузки старше суток очищаются при запуске.

### Применение

Если при нажатии «Обновить» и после загрузки лаунчер свободен, начинается установка. Иначе пакет остаётся готовым, а кнопка «Установить и перезапустить» становится доступна после освобождения. Уход из настроек во время загрузки также оставляет пакет для явного применения.

`InstanceStore.TryBeginAppUpdateAsync` атомарно проверяет launch/content leases, очередь установок, очистку удалённых сборок и зарезервированные каталоги восстановления, затем блокирует новые операции до окончания попытки. Дополнительно проверяются состояния `GameLaunchCoordinator`, очередь импорта архивов и `PlaytimeCoordinator.HasActiveProcessesAsync`: последний учитывает точные PID/время старта игры и помощника из ledger/journal, включая удалённые сборки. Ошибки чтения не разрешают установку.

`MainWindow.ApplyAppUpdateAsync` выполняет `INavigationGuard`, блокирует действия и начало новых импортов, через `UserSettingsService.WaitForPendingSavesAsync` дожидается начатых записей настроек, останавливает polling игрового времени и сохраняет его итог. Ошибка сохранения параметров игры запрещает замену приложения. `WindowsAppUpdateService.DeployAsync` регистрирует автоматический перезапуск через `RegisterApplicationRestart` и вызывает `Windows.Management.Deployment.PackageManager.AddPackageAsync` с `ForceTargetApplicationShutdown`. Для обновления сразу после запуска ожидается достижение 61 секунды монотонного времени процесса: Restart Manager требует минимум 60 секунд работы. Во время подготовки UI показывает состояние установки. При ошибке снимаются блокировки, возобновляются polling и очередь импорта; повреждённый пакет можно скачать снова, ошибку развёртывания — повторить.

Подпись и доверие сертификату проверяет Windows; клиент не импортирует `Hako.cer` и не ослабляет проверки. Name/Publisher и данные пользователя сохраняются при штатном обновлении MSIX. Непрерывность доверия сертификату обеспечивается существующей подписью CI. Предыдущие клиенты без этой функции нужно один раз обновить вручную. Запущенная Minecraft не завершается ради обновления.
